🔄 TRANSACTION LIFECYCLE
───────────────────────────────────────────────────────────────────────────────

STAGE 1: CREATION
  ├─ Staff takes action (receive, sell, or adjust)
  ├─ System records immediately
  └─ Database updated in real-time

STAGE 2: RECORDING
  ├─ Transaction stored permanently
  ├─ Timestamp automatically set
  ├─ Staff member automatically recorded
  └─ No editing or deletion possible

STAGE 3: VIEWING
  ├─ Staff can view in: Staff > Transactions
  ├─ Admin can view in: Admin > Transactions
  ├─ Search and filter available
  └─ Statistics calculated

STAGE 4: REPORTING
  ├─ Data available for analysis
  ├─ Revenue calculations
  ├─ Inventory movement tracking
  └─ Staff attribution visible

🎯 TRANSACTION TYPES AT A GLANCE
───────────────────────────────────────────────────────────────────────────────

TYPE: IN (Stock In)
  ├─ When: Items received from suppliers
  ├─ Example: "50 books from Star Paper Corp"
  ├─ Color: GREEN badge
  ├─ Effect: Inventory quantity increases
  └─ Sample: 3 records in system

TYPE: OUT (Stock Out)
  ├─ When: Items sold to customers
  ├─ Example: "25 books sold to customer"
  ├─ Color: RED badge
  ├─ Effect: Inventory quantity decreases
  ├─ Automatic: Created when sales completed
  └─ Sample: 3 records in system

TYPE: ADJUSTMENT
  ├─ When: Inventory corrections needed
  ├─ Example: "-5 damaged units removed"
  ├─ Color: YELLOW badge
  ├─ Effect: Adjusts quantity up or down
  └─ Sample: 1 record in system
