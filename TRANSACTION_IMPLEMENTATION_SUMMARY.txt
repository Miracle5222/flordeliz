## How Transactions Are Recorded

### INVENTORY TRANSACTIONS (Automatic)
```
Event: Add Inventory Item
Module: Staff → Inventory → Add New Item
Creates: inventory_transactions record (type='in')
Records: Product name, quantity, timestamp, user

Event: Record a Sale
Module: Staff → Sales → Create Sale
Creates: 
  1. sales_transactions record
  2. inventory_transactions record (type='out')
  3. Updates inventory quantity
Records: Amount, notes, timestamp, user

Event: Inventory Adjustment
Module: Manual correction
Creates: inventory_transactions record (type='adjustment')
Records: Item, quantity change, notes, user
```

### SALES TRANSACTIONS (Automatic)
```
Event: Direct Sale / Counter Sale
Module: Staff → Sales → Create Sale
Creates: sales_transactions record
Records: Date, amount (₱), notes, user, timestamp
```

## Database Tables Involved

### Primary Transaction Tables
```
inventory_transactions
├─ Stores all stock movements
├─ Fields: id, product_id, material_id, transaction_type
├─ Transaction types: in, out, adjustment
└─ Links: product (via product_id), user (via created_by)

sales_transactions
├─ Stores all direct sales
├─ Fields: id, transaction_date, total_sales, notes
├─ Links: user (via created_by)
└─ Records immediate sales transactions
```

### Supporting Tables
```
inventory
├─ Stores product information
├─ Updated when sales occur
└─ Linked from inventory_transactions

inventory_materials
├─ Stores material information
├─ Alternative product source
└─ Linked from inventory_transactions

users
├─ Staff and admin user records
├─ Identifies who recorded transaction
└─ Linked from created_by field

sales, sale_items
├─ Store order information (scheduled deliveries)
├─ Different from sales_transactions (direct sales)
└─ Do NOT auto-create sales_transactions
```

## How It Works - End to End

### SCENARIO: Staff Records Sale

**Step 1: User Action**
```
Staff logs in and goes to Staff → Sales → Create Sale
Selects product, enters quantity, confirms
```

**Step 2: Application Processing**
```
Script validates input
Calculates totals
Starts database transaction (all-or-nothing)
```

**Step 3: Database Inserts**
```
INSERT INTO sales_transactions
  (transaction_date, total_sales, notes, created_by)
  → Creates record with timestamp

INSERT INTO inventory_transactions
  (product_id, transaction_type, quantity, notes, created_by)
  → Creates 'out' type record

UPDATE inventory
  SET quantity = quantity - [amount]
  → Deducts from stock
```

**Step 4: Verification**
```
All three operations succeed
Database transaction committed
User sees success message
```

**Step 5: Data Visible**
```
Transactions → Inventory Tab
  → Shows Stock Out record (red badge)
  
Transactions → Sales Tab
  → Shows Sale Transaction record (₱amount)
  
Dashboard → Inventory
  → Shows updated stock quantity
```
